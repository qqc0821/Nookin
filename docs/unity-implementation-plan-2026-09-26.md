# Nookin：Unity 技术方案复审与最小验证范围

复审日期：2026-09-26。本次是仓库检查、资料核对和方案修订，未开发原型或运行 Unity。默认 macOS 优先，目标仍是 MateEngine 类丰富动作与桌面互动。

## 1. 结论与原方案需要修正的地方

保留 Unity，但缩小第一轮范围。原方案是技术路线草案，还不是严格的最小验证方案：真实窗口停靠过早进入首轮；只转动一根骨骼不足以验证动画播放和切换；提前固定 FBX/Humanoid 增加了资产转换步骤；缺少可重复的验收条件和失败处理规则。

建议顺序：**A 基础桌宠技术验证 → B 真实窗口互动验证 → C 动作库复用验证**。A 是最小可运行版本；要证明用户期望的 MateEngine 类路线，B、C 也必须通过。A 成功不能代表完整产品可行性已被验证，也不等于需求或商业价值得到验证。

## 2. 当前项目事实

- 当前工作区有素材和方案文档，未发现 package.json、electron/、src/ 或 Unity 工程。AGENTS.md 里的 Electron MVP 操作说明与当前工作区不一致，因此不能按已有 Electron 工程可复用来决策；这不是对其他分支或历史版本的判断。
- v3 GLB 约 4.4 MiB，31,756 顶点、41,532 三角面，1 套蒙皮使用 48 个关节、3 张内嵌贴图；有骨架与蒙皮，没有动画片段或表情形变目标。
- 用户已观察到挥手时肩膀、袖子变形。这属于资产/动作适配待检查项，不能直接否定引擎，也不能把简单动作成功当成成品资产合格。
- 此前本机 Blender 启动崩溃，首轮不依赖 Blender 转换或修模。Unity 构建、透明窗口、输入穿透、性能均尚未实测。

## 3. 是否有更好的实现方法

| 路线 | 对当前目标的判断 |
|---|---|
| Unity + 当前 GLB + 单透明窗口 | 推荐。直接使用已有素材，同时保留后续 Animator、动作混合和人形动作复用路线 |
| Electron + Three.js | 能做基础桌宠，但当前没有可复用工程；透明窗口不能自动解决命中穿透，也需补齐复杂动作和原生窗口追踪。只有 Unity 的桌面集成或常驻开销实测不合适时，再做针对性对照 |
| 原生 macOS 窗口 + 原生 3D 渲染 | 系统窗口控制直接，但需另建模型导入和动作工作流；对当前强调丰富动作的目标，不作为第一选择 |

这是工程判断，不是三种方案的实测性能排名。Electron 官方也将透明显示与鼠标事件穿透作为不同事项说明。[Electron 窗口文档](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)

采用 Unity 6 中兼容所需插件的受支持稳定版本，实施时固定编辑器补丁和依赖版本。使用单场景、单角色、单透明窗口，URP 先关闭 HDR、后处理与非必要阴影，保持背景 alpha。UniWindowController 是窗口控制候选；透明效果必须在独立构建中判断，且存在单窗口限制。定位具体失败后再决定是否补原生桥，不预先建设完整平台框架。[UniWindowController 文档](https://github.com/kirurobo/UniWindowController)

v3 用 glTFast 在编辑器导入为角色 Prefab。首轮使用当前骨架的 Generic Animator 或等效本地骨架动画绑定，不要求 Humanoid，也不强制转 FBX。glTFast 支持蒙皮，但 Mecanim 片段需额外接线；导入模型不等于自动得到 Controller 或有效人形 Avatar。[Unity glTFast 功能表](https://github.com/Unity-Technologies/com.unity.cloud.gltfast/blob/main/Packages/com.unity.cloud.gltfast/Documentation~/features.md)

## 4. A：最小可运行版本

用户可见闭环：**启动后出现在桌面 → 简单待机 → 点击后回应并回到待机 → 拖动改变位置 → 透明区域仍可操作下面的应用 → 正常退出。**

限定当前 Mac、单显示器、当前桌面空间、普通非全屏应用。保留 Dock 图标和系统退出入口，重启居中即可。首轮不做位置记忆、设置面板、菜单栏扩展、窗口停靠、走路/坐姿、精细权重修复、眨眼口型、AI、语音、音乐响应和 Windows。

### 实现顺序

1. **先验证桌面窗口。** 用简单占位物构建 macOS 应用，确认透明与基本点击穿透，尽早暴露平台问题，然后接入角色。
2. **接入角色和真实动画片段。** 导入 v3，在 Unity 编辑器内制作两个极简单的 .anim：小幅头部/躯干待机、短暂点头回应。曲线绑定到当前骨架路径，保存为工程资源并打进构建，由 Animator 播放和切换。无需新 Tripo 动画。直接转骨骼只作导入诊断，不作为动画系统最终验收。
3. **闭合交互。** 只用 Idle / React / Dragging 三个状态。点击触发回应，拖动打断回应，释放回待机。角色位移由窗口位置控制，禁用动作根位移，避免重复移动。

只需角色/动画、交互状态、窗口控制三个小模块。暂不引入服务端、通用插件框架或复杂行为树。

窗口围绕角色与动作留出边距，使用正交相机。鼠标命中采用随骨骼移动的少量头/身碰撞体，不做高面数网格求交或逐帧读取渲染像素。穿透时仍须能获取鼠标位置，不能只依赖窗口收到的鼠标进入事件；按下后保持拖动状态直到松开，避免离开角色轮廓就丢失拖动。统一屏幕逻辑坐标与 Unity 像素的换算，包含 Retina 缩放。

原素材只读保留，工程使用副本。v3 的可选材质扩展不视为必须支持：若材质有差异，先用基本 PBR 和已有贴图验证渲染并记录差异，不能把着色器问题误判为骨骼失败。

### A 的验收

下列次数和阈值是建议的首轮门槛，不是已测结果；必须在独立 macOS .app 中完成。

| 验证项 | 操作 | 通过条件 |
|---|---|---|
| 可运行交付物 | 关闭编辑器，从 Finder 连续启动 3 次 | 都能显示角色，无缺失材质、依赖或启动异常 |
| 动画和切换 | 待机 2 分钟，点击回应 20 次，并在回应中拖动 | 有骨骼形变；回应结束或释放后回待机，无卡状态、累计漂移或整体网格散开 |
| 透明与命中 | 在下层按钮、文本区、滚动区分散操作 30 次；另点击角色 20 次 | 无不透明背景矩形；透明区域操作全部到达下层，角色点击全部触发回应 |
| 焦点 | 在文本编辑器输入，同时让角色待机、鼠标经过 | 不因自主动画或鼠标经过丢失焦点；角色点击后的焦点变化单独记录并修正 |
| 拖动和退出 | 连续拖动 20 次，包含快移、鼠标离开轮廓后松开、靠近屏幕边缘 | 不丢松开、不粘住鼠标、不永久离屏；系统退出和重启始终可用 |
| 稳定性与开销 | 独立构建运行 30 分钟，记录帧时间、CPU/GPU、常驻内存 | 无崩溃和持续新增错误；目标 30 FPS，交互阶段 p95 帧间隔≤50 ms；预热后内存无持续增长趋势。CPU/GPU 实测作为常驻取舍依据，不能仅凭帧率宣称低功耗 |

已有肩部瑕疵可以暂时接受；人物消失、蒙皮炸开、透明区域阻挡操作、输入焦点失控不能接受。只为状态切换与坐标转换补必要的自动检查；透明、穿透、焦点仍须实际操作。编译成功不能代替验收。

## 5. B、C：基础演示不能替代的验证

### B：真实窗口互动

A 通过后，增加一个 macOS 窗口追踪适配器，以 Accessibility 查询/观察为候选；先只跟踪选定的 Finder 或浏览器普通前台窗口，必要时低频校验该目标位置。用进程和窗口引用建立本次会话身份，不假设所有应用都有统一永久编号。[Apple AXUIElement 文档](https://developer.apple.com/documentation/applicationservices/axuielement)

先用脚底锚点站在窗口上缘，不要求坐姿。移动/缩放时跟随；最小化、关闭、失去目标或前台切到另一应用时脱离并回安全位置。不承诺任意窗口遮挡合成、全屏/Spaces 或多屏兼容。权限不可用时，A 的基础桌宠继续工作，提示窗口互动不可用。

验收：Finder 和浏览器分别移动/缩放 10 次，静止后锚点误差≤5 个屏幕逻辑点；最小化、关闭、前台切换后 1 秒内恢复安全位置；拒绝或撤销权限不崩溃、不反复弹窗。保存跟随和脱离录像。未通过时只代表基础桌宠成立，真实窗口互动仍未验证。

### C：动作库复用

A 的本地动画只证明播放链路，不能证明 Humanoid 重定向、坐姿或任意动作库兼容。批量准备动作前，再取一个可合法使用的简单人形片段，验证当前角色的 Avatar 映射和重定向。优先采用成熟的 FBX/Humanoid 工作流，但 FBX 格式本身不保证绑定姿态、骨骼映射或权重正确。

验收：Avatar 映射有效；外部片段能在当前角色播放并与待机切换，根节点不跳变；区分映射失败与已知局部变形。失败先处理姿态、映射或资产，必要时使用当前骨架的专用动画。改格式或换引擎本身不算修复。

## 6. 失败处理与最终交付证据

| 失败处 | 下一步 |
|---|---|
| 模型导入/材质 | 用已知正常的简单蒙皮资源对照，区分导入配置与本模型问题，只修工作副本 |
| Animator 切换 | 检查曲线路径、根节点和 Controller 绑定，不再要求用户盲目重复导出 |
| 透明/穿透/焦点 | 用占位物复现，检查插件和渲染设置；定位原生窗口问题后再做最小桥接。仍不可行或开销过高，再比较 Electron/原生方案 |
| 窗口跟随 | 缩小支持范围或暂限屏幕边缘；标注该能力未通过 |
| 常驻开销 | 检查渲染区域、帧率、后台活动、阴影，再决定是否更换路线 |

实施后交付：可启动的 .app、完整交互闭环录像、验收表、运行日志和资源记录；注明编辑器、插件、系统、硬件与显示缩放。A、B、C 分别标注通过、失败或未测。性能只代表被测设备和场景。

AI 留到后续，通过有限意图接口触发行为即可；当前不开发独立 AI 服务。此次只更新方案，上述开发与验收尚未执行，当前无需用户继续生成或上传素材。
