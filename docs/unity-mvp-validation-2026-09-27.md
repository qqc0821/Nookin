# Unity 桌宠最小验证结果

日期：2026-09-27。环境：macOS 15.5、Apple M4、Unity 6.3.25f1 ARM64。构建产物：`unity/NookinMvp/Builds/NookinMvp.app`。

| 项目 | 结果 | 证据与边界 |
|---|---|---|
| GLB 导入与显示 | 通过 | v3 原件的骨骼节点缺失静止姿态，直接导入会变形；只在项目副本中根据 inverse bind matrices 恢复 48 根骨骼变换，Unity 正面画面显示完整角色。原件 SHA-256 为 `71f0093097ce68c66db5878ac2e12b0b96665c2fa1193e8766fc8c1232d402fc`，原样备份一致。 |
| macOS 独立应用 | 通过 | Unity 批量构建退出码 0；在图形桌面打开最终 `.app`，显示角色。 |
| 点击动作 | 通过 | 用户真实鼠标点击后看到点头；运行日志记录 `Nookin react triggered`。最小动作由 Unity Animator 的 Idle/React 片段控制。 |
| 拖动窗口 | 通过 | 用户真实鼠标拖动后窗口移动；运行日志记录 `Nookin drag ended`。 |
| 透明区域穿透 | 通过 | 用户把桌宠移到普通窗口上方，点击桌宠窗口四角空白处，下方窗口可直接收到点击。 |
| 重复次数、焦点、稳定性 | 未完成 | 尚未按方案执行 20 次点击/拖动、30 次穿透、30 分钟运行和焦点测试。构建及本次实际操作未发现崩溃，但不能代替长期验收。 |
| 性能 | 仅单点采样 | 最终应用启动约 1.5 分钟时 `ps` 显示 RSS 约 253 MiB、CPU 约 26.6%（macOS `ps` 口径）。未形成稳定区间或电池功耗结论。 |
| B：真实窗口跟随 | 未开始 | 尚无 Accessibility 窗口追踪适配器；不能宣称 MateEngine 类窗口停靠已可用。 |
| C：外部动作库复用 | 未开始 | v3 只有骨架和蒙皮，没有自带动画片段；Unity 本地动作播放已验证，Humanoid 映射和外部动作重定向未验证。 |

结论：**Unity + 修复后的现有 GLB + UniWindowController 可以实现基础桌宠技术闭环**。它支持把后续 AI 意图映射到 Animator 行为，但尚未实现 AI 接入。若目标是 MateEngine 级别的丰富动作和真实窗口互动，仍需 B、C 两项独立验证，并处理肩袖权重与常驻开销。截图工具只捕获独立应用窗口，透明性结论以用户实际桌面操作为准。

## 后续动作变更：点头改挥手

应用户要求，当前构建的点击回应已从 `React.anim` 点头改为 `Wave.anim` 挥手。项目副本 `nookin-rigged-wave.glb` 只调整挥手侧上臂、前臂、手的静止旋转中心及对应 inverse bind matrices；48 个关节的最大静止矩阵误差约 `2.81e-6`，原始 v3 文件未变。Unity 关键帧渲染检查了抬手、摆手和放下阶段，角色轮廓和袖子保持可辨；批量构建成功，独立应用已在桌面打开。真人鼠标对新挥手动作的点击与复位确认仍待反馈。
